# ADR-001: Bedrock AgentCore Memory Architecture for Session Persistence and Semantic Long-Term Outcomes

**Status:** Accepted  
**Date:** 2026-09-05  
**Deciders:** Rebuttal Team  
**Milestone:** M3 AgentCore (HAC-9 / R-07)  

---

## Context

In an autonomous chargeback defense agent, two distinct memory scopes are necessary:
1. **Short-Term Session Persistence (Human-in-the-Loop Interrupts):**
   When high-value or policy-gated disputes (e.g., Scenario S2 at $340 > $200 approval threshold) encounter the `ApprovalGate`, the agent must pause execution with an interrupt (`stop_reason="interrupt"`), emit an SMS notification, and persist the execution graph / agent state so that when the merchant later responds (e.g., via SMS reply or dashboard approval payload in a separate invocation), the executor agent can resume from the exact tool-call interrupt boundary.
2. **Long-Term Cross-Case Outcomes (Semantic Retrieval):**
   The agent must remember past dispute outcomes by dispute reason (e.g. `product_not_received`, `fraudulent`, `canceled_recurring_billing`), recording the action taken, outcome (won/lost), amount, and winning factors. When investigating new disputes, the `history` node retrieves past outcomes to inform the win probability assessment and evidence narrative drafting.

---

## Decision

1. **Memory Resource & Semantic Strategy:**
   - Use AWS Bedrock AgentCore Memory (`rebuttal_mem-Idf0xfCGuL`) in region `us-east-1`.
   - Add a semantic memory strategy `merchant_outcomes` configured with namespace `/merchant/{actorId}/outcomes` (and template `/merchant/{actorId}/outcomes`).
2. **Session Persistence with AgentCoreMemorySessionManager:**
   - Equip the Strands `executor` agent with `AgentCoreMemorySessionManager(AgentCoreMemoryConfig(memory_id, session_id=dispute_id, actor_id=merchant_id))` using the runtime IAM execution role in AWS (or configured profile locally).
   - Interrupt states generated by `ApprovalGate` are saved to the Bedrock AgentCore Memory data plane and restored upon subsequent invocation turns.
3. **Dispute Closure & Event Recording:**
   - The runtime `dispute.closed` event handler logs short-term conversation events and indexes structured outcome records (`{reason, action, outcome, amount, dispute_id}`) under `/merchant/{actorId}/outcomes/`.
4. **History Agent Enrichment:**
   - `get_merchant_history_and_policy` integrates with `retrieve_past_outcomes(reason)` to incorporate historical win/loss precedent into policy evaluation.

---

## Consequences

- **Durability:** Execution states survive container cold starts and serverless container lifecycles in Bedrock AgentCore.
- **Explainability:** History and strategist agents ground decisions in historical evidence packets that won in the past.
- **Fallback:** If AgentCore memory session state fails to persist, an optional fallback to `S3SessionManager` is documented, while semantic long-term memory remains on Bedrock AgentCore.
